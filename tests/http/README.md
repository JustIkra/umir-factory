# HTTP acceptance module

This module contains the existing selected HTTP suite, strict backend clients, and bounded synthetic transport fixtures. The backend shared foundation is implemented. Backend F3 acceptance remains incomplete: two case bindings exist and 65 cases return explicit unimplemented errors. Protocol doubles in unit tests verify infrastructure only. They do not prove application acceptance.

Use Go 1.26.9, golangci-lint 2.14.0 and go-arch-lint 1.19.0. From the Factory root, run `make check-http`, `make check` and `make go-readiness`. The complete Factory gate also requires explicit `WAREHOUSE_DIR` and `SERVING_DIR` for its controlled business workspace. Run module integrity checks with `GOWORK=off go mod verify`. Private descriptors and configuration paths must have canonical parents without symlinks; use a canonical temporary directory on macOS.

The parallel writer contract is recorded under the root workspace at `.memory-base/plans/backend-e2e/runs/backend-e2e-20261012/F3/recovery-parallel/private-consumer/follow-up/scenario-contract.json` and `scenario-contract.md`. The E1/E2, E3/E4 and E5 writers own `cmd/acceptance/backend_e12.go`, `backend_e34.go` and `backend_e5.go`, respectively, plus matching group-local helper/test files. The integrator owns the shared scenario input, setup, dispatch and result collection.

Each backend case has a 30-second budget and fresh API-created scopes. Shared Auth/session/clock state persists inside a descriptor. Global capacity, storage migration/corruption and destructive cases require a separate runner-owned project. Controls and restarts are serial; public HTTP calls support concurrent scenario actions. No reset operation is invented.

The embedded operational schema and examples use RPC 1.1.0 and the independently reviewed bindings digest `af215b378140b8e690523fc537007679b8c2599ed3039f7f2a0c651a64c59410`. Feedback observations select exact original namespace/submission pairs. The client checks pair coverage, unique real jobs, receipt edges, canonical redacted digests, owner clocks and request correlation. Fresh reads use fresh control IDs. Exact process-cache replay retains its original request and reply, including incomplete replies. A completed clock advance in the same process is permitted; the current healthy clock must remain stable across replay, and the original instance must still match. Business retries retain the original command, payload and namespace.

Restart verifies project/service/image/helper/config ownership, checkpoints the owner clock, preserves the exact Auth/Feedback named volume, and requires a new instance with the saved clock. After start, readiness polling waits for the private control transport within the remaining case budget. Each read revalidates ownership. Only transport startup failures and retryable read-only NotReady/WaitExpired replies are polled. Terminal refusals and mutations are never retried. Warehouse/Serving have no durable volume. A successful restart helper does not prove recovered business facts, empty memory, new epochs or registry reconciliation. Scenario writers must measure those facts through supported real interfaces.

Secrets, OTP, cookies, public raw bodies and private reply headers stay in private memory/files. Ordinary evidence includes only schema/status, resource IDs, redacted projection fields and identity/clock facts. Raw Auth/Feedback storage is never read. Missing provider capabilities return unavailable errors. The shared client supplies qualified private-service routing and real Auth token acquisition. Signer rotation, arbitrary config replacement, migration, corruption and missing-tzdata owner profiles remain pending. Real J1/E execution must wait for all groups and reviewed owner providers.

The unpublished backend-run v2 amendment requires exactly five privateServiceURLs. The decoder validates the reviewed strict overlay, rejects duplicate/unknown/trailing JSON and canonicalizes no endpoints. Each URL must already use HTTP, literal 127.0.0.1 and a decimal port from 1 to 65535, without leading zeros, credentials, path, query or fragment. Private URLs are unique and distinct from the public Gateway and sink controls. Existing selected/version 1 commands retain their original contracts. The backend v2 command never downgrades.

Before every private request, public Gateway call or sink control HTTP probe, the shared client validates initial evidence.json project/container/image bindings, the complete owned inventory and fresh target discovery. It checks project/service/run labels, exact images and container IDs, healthy owner readiness, every loopback publisher, and the exact Compose port result. The private targets are 8080 except Gateway 8082. Public Gateway remains 8080; sink controls remain 8025 and 8026. A stale, replaced, foreign or remapped listener fails before HTTP. Each discovery has a maximum 60-second deadline within the caller budget. Docker reads have 10-second and 256 KiB limits; endpoint output has a 128-byte limit. Control-binary archive copies keep their separate 8 MiB bound.

Private helpers are privateCall, privateReplay and privateReject. They bind operation IDs to the frozen concrete owner route. Normal requests require the frozen body schema and an opaque Auth-issued token where serviceJWT is declared. Credential names refer to real target-scoped private files; owners still enforce their business ACLs. privateReplay preserves caller-retained valid bytes and sends once. privateReject alone permits malformed headers, body or token values and requires an expected 4xx/5xx status. Every response retains frozen schema validation. Private HTTP has a five-second request limit, 1 MiB body limits and 16 KiB request/response header limits. Its transport connects only to the qualified literal endpoint, disables proxies and redirects, and retries no mutations. Raw replies stay private; public observations contain only target, operation, status and schema facts.

privateAuthLogin uses Auth private CSRF/preauth and session issuance. scopedAuthToken uses that real session through Auth authorize; serviceAuthToken and anonymousAuthToken call the existing real Auth interfaces. Only Auth signs tokens. The helper never extracts Gateway cookies or reads Auth/Feedback persistence. The returned token wrapper has no public raw-token constructor. Missing owner support or an ACL refusal stays an explicit failure.

restart preserves the saved owner clock and mounted-volume proof. recreate also permits a new container after one owned stop/config update/force-recreation. Both require a new healthy owner instance, the unchanged saved instant/generation, preserved exact mounts and reviewed image, and fresh mapping discovery. After qualification, one mode-0600 private-probe-state.json atomically records the current descriptor, complete container bindings and before/after clock proof; only then does in-memory routing advance. The runner's initial evidence stays immutable. Any mutation, clock, mapping or metadata-write failure blocks subsequent HTTP. Gateway recreation that changes the public Origin requires a new runner invocation and is rejected. Startup retries remain read-only, bounded and use fresh control IDs. No automatic mutation retry or committed-outcome inference is added.

Every public request crosses the shared `backendPublicClient.Do` boundary, including raw rejection requests. It qualifies current ownership before connecting, preserves session-local cookies, and applies the same endpoint, deadline, redirect and response-size limits. Qualification and state updates are synchronized. Qualified public response leases permit overlapping HTTP calls. Private calls and restart remain exclusive and wait for open responses within the caller budget; EOF, read failure, Close and cancellation release a lease once. Controls and evidence collection remain serial integrator operations.

Final restart discovery must match the exact container that supplied the new-instance, saved-clock and mount proof. A later replacement rejects restart/recreation, leaves the owner unqualified and writes no new metadata or successful restart receipt. Gate records use an explicit nonsecret environment allowlist.
