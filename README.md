# UMIR Factory

Репозиторий сборки одного ресторана. Он фиксирует совместимые образы четырёх сервисов и запускает их через Docker Compose.

| Репозиторий | Ответственность |
| --- | --- |
| [umir-gateway](https://github.com/JustIkra/umir-gateway) | Единый API-вход. |
| [umir-serving](https://github.com/JustIkra/umir-serving) | Меню, предложения заказов, стоп-лист и рекомендации. |
| [umir-warehouse](https://github.com/JustIkra/umir-warehouse) | Поставки, партии, FEFO, просрочка и фиксация продажи. |
| [umir-frontend](https://github.com/JustIkra/umir-frontend) | React и раздача интерфейса. |

Сервисы сейчас содержат запускаемые каркасы. Бизнес-логика и экраны ещё не реализованы.

## Запуск опубликованной сборки

Требуются Docker Engine и Docker Compose v2.

```sh
cp .env.example .env
docker compose config --quiet
docker compose pull
docker compose up -d --wait
```

Frontend доступен на `http://127.0.0.1:8080`, gateway — на `http://127.0.0.1:8081`.
Проверка цепочки: `GET /api/serving/healthz` и `GET /api/warehouse/healthz` через любой из этих портов.
Проверки `/healthz` подтверждают работу процессов, а не готовность бизнес-функций.

Склад и обслуживание доступны внутри сети Compose. Порты по умолчанию привязаны к loopback.
Время — `Europe/Moscow`.

## Локальная сборка

Расположите пять репозиториев рядом в одном каталоге.

```sh
docker compose -f compose.yaml -f compose.dev.yaml up -d --build --wait
```

## Выпуск и обновление

1. Участник создаёт рабочую ветку и PR в сервисном репозитории.
2. CI проверяет исходный код и Docker-сборку.
3. `JustIkra` объединяет PR или обновляет `main`.
4. CI/CD публикует `ghcr.io/justikra/umir-<service>:sha-<полный SHA>` для amd64 и arm64.
5. Создайте PR сюда с выбранными SHA в `compose.yaml`.
6. После проверки и merge выполните команды запуска опубликованной сборки.

Фабрика проверяет Compose и соответствие образов своим сервисам. Она не публикует собственный контейнер.
Публикация сервисных образов использует штатный `GITHUB_TOKEN`. Деплой на сервер выполняется отдельно.

## Совместная работа

Все репозитории публичные. Любой пользователь GitHub может создать issue, fork и PR.
Приглашённые участники могут создавать и обновлять рабочие ветки в исходных репозиториях.
Обновлять `main` и объединять PR может только `JustIkra`.
Настоящие `.env`, токены и рабочие данные ресторана в Git не сохраняются.
