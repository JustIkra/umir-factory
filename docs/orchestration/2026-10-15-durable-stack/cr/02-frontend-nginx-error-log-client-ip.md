# CR 02 — frontend: error_log Nginx содержит адрес клиента и строку запроса

Группа: frontend, волна 1 (задача F1-3/F1-4).

**Что.** Правило ПДн (раздел 8 главной спеки) запрещает адреса клиентов в логах. Журнал доступа Nginx переведён на свой `log_format` без `$remote_addr`, `$http_referer` и строки запроса (проверено тестом). Журнал ошибок (`error_log`) формат задать не позволяет: строка уровня `error` содержит `client: <адрес>`, `request: "GET /path?query"` и `host`. Пример, снятый на живом экземпляре: `upstream prematurely closed connection ..., client: 172.24.0.1, server: _, request: "GET /api/drop?secret=abc HTTP/1.1", upstream: ..., host: ...`. После F1-4 `client:` — настоящий адрес клиента (через `real_ip`). Уровни `notice` и `warn` дают то же самое; убрать такие строки можно только уровнем `crit`, но тогда пропадает диагностика обрывов и таймаутов Gateway.

**Зачем.** Хранение IP клиентов в журнале ошибок противоречит правилу ПДн, если оно распространяется на `error_log`.

**Кого затрагивает.** G-factory (ротация и срок журнала Nginx 14 дней, доступ), оркестратор (трактовка правила).

**Предложение.** Вариант A (принят по умолчанию в ветке, ничего не менялось): оставить `error_log` образа как есть (stderr контейнера), factory фиксирует для него срок 14 дней, без выгрузки наружу, доступ только у оператора стенда. Вариант B: `error_log stderr crit;` в `nginx.conf`, ошибки апстрима видны по статусам 502/504 и `request_id` в журнале доступа; frontend меняет одну строку по решению оркестратора.

**Решение оркестратора (16.10):** вариант B — `error_log stderr crit;`, C55 главной спеки.
