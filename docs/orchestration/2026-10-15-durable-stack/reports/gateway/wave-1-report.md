## Ruling (отклонения и решения)

Подробно в `progress.md`. Главное:
- `/readyz` в волне 1: только `http` и `scheduler`.
- Снимок реестра для `PUT …/registry` до 2 с допустим; подтверждающее чтение начинается после прихода запроса и объединяется между вызовами (метки порядка чтений).
- Усечённая бюджетом итерация планировщика — прогресс (`degraded`, не `down`).
- Закрытые рестораны — отдельное множество с тем же пределом; `subscribers`/`runtimes` лениво (иначе 10 000 scope >2 МиБ). Тест G4 про слот закрытого scope изменён по спеке.
- IPv6 нормализуется по /64 и без конфигурации. `GATEWAY_TRUSTED_PROXY_CIDRS` — только CIDR.
- Диапазоны, которых нет в спеке: SSE-лимиты 1–100000; сводка: дедлайн 1–29 с, параллелизм 1–32, байты 1 МиБ–1 ГиБ; `_FILE` до 4096 байт.
- W1.12 выявила настоящее расхождение: фасад Auth превращал `409 CommandConflict` с `outcome: unknown` в `503 AuthUnavailable`. Исправлено в `authclient/facade_failure.go`.
- Неизвестная подкоманда и лишние аргументы теперь отказ запуска (аргументы с `-` игнорируются).
- Записи об отказах пишутся для scoped-маршрутов и отчётов сводки; отказы фасада Auth (`/api/v2` операторские маршруты) в журнал не пишутся, ID туда пробрасывается.
- C54 (sticky SSE `hash` без `consistent`) на Gateway не влияет; отмечено в README.
