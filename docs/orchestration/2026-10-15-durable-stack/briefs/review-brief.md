Ты проверяешь всю ветку одного репозитория перед тем, как draft PR выйдет из черновика. Код не правишь и не коммитишь. Субагентов не запускаешь.

Параметры (worktree, ветка, подспека, волна, журнал, отчёт исполнителя) — в задании.

## Прочитай

1. Главная спека: `/Users/yahi3123/projects/umir-2026/docs/superpowers/specs/2026-10-15-durable-stack/00-orchestration.md`. Обязательно: разделы 2, 3, 5, 8, 10. Раздел 10 (решения C*) главнее подспеки.
2. Подспека: раздел своей волны и разделы 6–9.
3. Отчёт исполнителя `wave-<N>-report.md` и журнал группы. Ruling там — осознанные решения: оспаривай, только если они противоречат спеке или ломают поведение.
4. Дифф ветки:
   - `git -C <worktree> log --oneline origin/main..HEAD`
   - `git -C <worktree> diff origin/main...HEAD`
   Если дифф большой — читай по файлам. Прочитай его целиком.
5. `AGENTS.md` репозитория.

## Что проверять

1. **Полнота.** Каждый пункт раздела волны в подспеке: сделан, сделан частично или не сделан. Сверь с таблицей в отчёте исполнителя.
2. **Корректность.** Гонки, утечки горутин, дедлоки, ошибки ресурсов, неверные коды ошибок, граничные случаи, обратная совместимость конфигурации.
3. **Тесты.**
   - Проверяют ли они поведение, а не реализацию?
   - Покраснеют ли при поломке?
   - Нет ли тестов, которые ничего не утверждают?
   - Нет ли ослабленных сроков?
4. **Соответствие решениям C\*.** Имена, коды 429/503, ключи, переменные `_FILE`, роли и т. д.
5. **Документы.** README и CHANGELOG совпадают с кодом.
6. **Коммиты.**
   - Conventional Commits.
   - Без футеров `Co-Authored-By` и generated-by.
   - В диффе нет секретов и мусора (бинарники, временные файлы, `.superpowers`).

## Проверки

Запусти `make check` (Go — с `GOWORK=off GOTOOLCHAIN=go1.26.9`; frontend — `npx -p bun@1.4.3 npm run check` и `npm run test:nginx`). Сверь числа с отчётом.

Машина загружена другими агентами. Если тест падает по времени, перезапусти его отдельно с `-count=3`, прежде чем называть это дефектом.

Docker-контейнеры не запускай и не останавливай.
