## Незакоммиченные изменения

Это работа прерванного исполнителя.

- Если они соответствуют задаче плана, которая была «в работе», доведи их до зелёных тестов и закоммить.
- Если явно сломаны — убери их: `git stash push -u -m "durable-<группа>-<задача>-wip"`. Не удаляй. Запиши Ruling.

## Порядок работы

1. Продолжай с первой незавершённой задачи плана. Сделанные не переделывай.
2. Каждая задача:
   - падающий тест (убедись, что он красный);
   - код;
   - тесты пакета и `make check`;
   - коммит.
3. После каждой задачи:
   - строка в журнал: `- <дата время> T<N>: complete <SHA…>; тесты <числа>; Ruling: …`;
   - обнови файл тела PR `<группа>/wave-<N>-pr-body.md`.
4. Решения: `Ruling: <что> — <почему> — <цена ошибки>`. Остановка — только по разделу 7 главной спеки.
5. Чужой интерфейс → CR в `/Users/yahi3123/projects/umir-2026/.superpowers/sdd/2026-10-15-durable/cr/`.
6. Если тест падает по времени, перезапусти его отдельно: `-count=3`. Сроки не ослабляй.
7. Итоговые проверки (раздел 8 главной спеки). Go с `GOWORK=off GOTOOLCHAIN=go1.26.9`: `make tools`, `make check`, `make quality-test`, `make integration` (если объявлены). Frontend: `npm ci`, `npx -p bun@1.4.3 npm run check`, `npm run test:nginx`.
8. Самопроверка: весь `git diff origin/main...HEAD` против раздела волны подспеки, по пунктам.

## Коммиты

- Conventional Commits на английском, логическими группами.
- **Без** футеров `Co-Authored-By` и generated-by.
- CHANGELOG «Unreleased».
- `git diff --check`.

## Публикация

Решение пользователя: ветки публикует координатор.

- Не пушь.
- Не запускай `gh pr create` и `gh pr edit`.

**Сигнал «стоп» от координатора:**
- за 15 минут доведи текущий шаг до зелёного или убери незаконченное в stash с уникальным именем;
- обнови README, CHANGELOG, отчёт и тело PR (сделано / не сделано / почему);
- ответь.

## Границы

- Только своя волна (волна 2 ждёт G1), свой worktree и своя ветка.
- Чужие checkouts не трогай: `umir-*` в корне, `_backend-v2/*`, `dev/backend-v2`, `_wt/prod/*`, `_wt/review/*`.
- Спеки не правь.
- Запрещено: push, merge, force-push, теги, релизы, образы, настройки репозиториев, Figma, чужие контейнеры (порты 5432 и 6379).
- Секреты не печатай и не коммить.

Коротко:

- проверки одной строкой;
- CR;
- 3–5 строк главного.
